# Outils et construction.

@ npm
cat: outils
nom: npm
dev: Node Package Manager
alias: node package manager, npx, yarn, pnpm, npm install, npm run, npm ci, registry npm, node_modules
fr: Gestionnaire de paquets de l'écosystème JavaScript : il télécharge les bibliothèques dont un projet dépend dans le dossier node_modules, et lance les commandes définies dans package.json (npm run, npm test).
en: The JavaScript ecosystem's package manager: it downloads the libraries a project depends on into the node_modules folder, and runs the commands defined in package.json (npm run, npm test).
+fr: npm ci installe exactement les versions du fichier de verrouillage : c'est la commande à préférer en intégration continue. npx lance un outil sans l'installer durablement.
+en: npm ci installs exactly the versions in the lock file: it is the command to prefer in continuous integration. npx runs a tool without installing it permanently.
ex: bash
| npm init -y
| npm install vite --save-dev
| npm run build
| npx serve .
ex-fr: Créer un projet, ajouter un outil de développement, lancer un script, puis servir le dossier sans rien installer à demeure.
ex-en: Create a project, add a development tool, run a script, then serve the folder without installing anything permanently.
voir: package-json, lockfile, nodejs, paquet-logiciel, dependance
schema: outils-npm

@ nodejs
cat: outils
nom: Node.js
alias: node, nodejs, node js, deno, bun, runtime javascript, v8
fr: Environnement qui exécute JavaScript en dehors du navigateur, sur un ordinateur ou un serveur. Il a rendu possible d'écrire des serveurs web, des outils en ligne de commande et des scripts de build dans le même langage que les pages.
en: An environment that runs JavaScript outside the browser, on a computer or a server. It made it possible to write web servers, command-line tools and build scripts in the same language as web pages.
ex: bash
| node --version
| node -e "console.log(2 + 2)"
| node serveur.js
ex-fr: Afficher la version, exécuter une ligne de JavaScript, lancer un fichier.
ex-en: Print the version, run one line of JavaScript, run a file.
voir: js, npm, runtime, package-json

@ package-json
cat: outils
nom: package.json
alias: package json, scripts npm, main, type module, dependencies, devdependencies, manifeste npm
fr: Fichier à la racine d'un projet JavaScript qui le décrit : son nom, sa version, ses dépendances et ses scripts (npm run …). C'est le manifeste du projet pour npm.
en: The file at the root of a JavaScript project that describes it: its name, version, dependencies and scripts (npm run …). It is the project's manifest for npm.
ex: json
| {
|   "name": "code-en-clair",
|   "version": "1.0.0",
|   "scripts": { "test": "node build/essais.mjs" },
|   "devDependencies": { "vite": "^5.4.0" }
| }
ex-fr: Un package.json minimal : un script de test et une dépendance de développement à une version 5.4 ou compatible (^).
ex-en: A minimal package.json: a test script and a development dependency at version 5.4 or compatible (^).
voir: npm, lockfile, semver, dependance, manifest

@ lockfile
cat: outils
nom: Fichier de verrouillage
nom-en: lockfile
alias: package-lock.json, yarn.lock, pnpm-lock.yaml, lock file, verrouillage, versions exactes, reproductible
fr: Fichier généré par le gestionnaire de paquets qui note la version exacte de chaque dépendance installée, y compris les dépendances des dépendances. Il garantit que deux installations donnent exactement le même résultat.
en: A file generated by the package manager that records the exact version of every installed dependency, including dependencies of dependencies. It guarantees that two installations give exactly the same result.
attention-fr: On le versionne avec Git (contrairement à node_modules) : c'est lui qui rend une construction reproductible.
attention-en: It is committed to Git (unlike node_modules): it is what makes a build reproducible.
voir: npm, package-json, semver, dependance, gitignore

@ bundler
cat: outils
nom: Bundler
nom-fr: empaqueteur
alias: webpack, vite, rollup, esbuild, parcel, empaqueteur, bundle, tree shaking, code splitting, chunk
fr: Outil qui rassemble les nombreux fichiers d'un projet (modules JavaScript, CSS, images) en quelques fichiers optimisés à envoyer au navigateur, en supprimant le code inutilisé et en découpant le résultat en morceaux (chunks) chargés à la demande.
en: A tool that gathers a project's many files (JavaScript modules, CSS, images) into a few optimized files to send to the browser, removing unused code and splitting the result into chunks loaded on demand.
voir: build, minification, transpilation, module, chunk
schema: outils-build

@ build
cat: outils
nom: Build
nom-fr: construction, compilation du projet
alias: construire, npm run build, dist, production build, chaîne de build, build tool, compiler le projet, artefact de build
fr: Ensemble des étapes qui transforment le code source d'un projet en un produit prêt à l'emploi : compilation, assemblage, minification, copie des ressources. Le résultat se range en général dans un dossier dist ou build.
en: The set of steps that turn a project's source code into a ready-to-use product: compilation, bundling, minification, copying resources. The result is usually placed in a dist or build folder.
+fr: Certains projets n'ont pas de build : leurs fichiers sont servis tels quels. C'est le cas d'un site en HTML, CSS et JavaScript « à la main ».
+en: Some projects have no build: their files are served as-is. That is the case with a site in hand-written HTML, CSS and JavaScript.
ex: bash
| npm run build
| ls dist
ex-fr: Lancer la construction, puis voir le dossier produit.
ex-en: Run the build, then look at the folder it produced.
voir: bundler, ci-cd, artefact, gradle, transpilation
schema: outils-build

@ transpilation
cat: outils
nom: Transpilation
nom-en: transpiling
alias: transpiler, transpileur, transpiler, babel, typescript, tsc, sass, source-to-source, compiler vers javascript
fr: Traduction d'un code source vers un autre langage de même niveau, par exemple du TypeScript vers du JavaScript, ou du JavaScript moderne vers une version que les vieux navigateurs comprennent.

@ minification
cat: outils
nom: Minification
nom-en: minification
alias: minify, minifier, uglify, terser, cssnano, .min.js, code minifié, obfuscation
fr: Réduction de la taille d'un fichier de code en supprimant ce qui ne sert qu'aux humains (espaces, commentaires) et en raccourcissant les noms de variables. Le code reste équivalent, mais devient illisible.
en: Reducing a code file's size by removing what only humans need (spaces, comments) and shortening variable names. The code stays equivalent, but becomes unreadable.
ex: js
| function additionner(premierNombre, secondNombre) { return premierNombre + secondNombre; }
| function a(n,o){return n+o}
ex-fr: Avant, la fonction lisible ; après minification, la même en 27 signes seulement.
ex-en: Before, the readable function; after minification, the same in just 27 characters.
attention-fr: Minifier n'est pas obfusquer ni protéger : c'est un gain de taille, pas de sécurité.
attention-en: Minifying is not obfuscating nor protecting: it is a size gain, not a security measure.
voir: bundler, source-map, compression, bande-passante

@ source-map
cat: outils
nom: Source map
nom-fr: carte des sources
alias: sourcemap, .map, carte de correspondance, debug minifié
fr: Fichier qui relie le code transformé (minifié, transpilé, empaqueté) au code source d'origine, pour que les outils de développement affichent les erreurs et les points d'arrêt dans le code qu'on a écrit.
en: A file that maps transformed code (minified, transpiled, bundled) back to the original source code, so that developer tools show errors and breakpoints in the code you wrote.
voir: minification, devtools, debugger, transpilation
schema: outils-source-map

@ lint
cat: outils
nom: Linter
alias: eslint, lint, linting, prettier, formatter, formateur, analyse statique, static analysis, stylelint, pylint, ruff
fr: Outil qui lit le code sans l'exécuter pour y repérer des erreurs probables, des risques et des écarts au style de l'équipe : variable inutilisée, comparaison douteuse, mauvaise indentation. Un formateur (Prettier) va plus loin : il réécrit le code pour l'uniformiser.
en: A tool that reads code without running it to spot probable errors, risks and departures from the team's style: unused variable, dubious comparison, wrong indentation. A formatter (Prettier) goes further: it rewrites the code to make it uniform.
ex: bash
| npx eslint src/
| npx prettier --write src/
ex-fr: Signaler les problèmes du dossier src, puis reformater tous ses fichiers.
ex-en: Report the problems in the src folder, then reformat all its files.
voir: hook, ci-cd, code-review, refactoring, test-unitaire

@ ci-cd
cat: outils
nom: CI/CD
dev: Continuous Integration / Continuous Delivery
nom-fr: intégration et livraison continues
alias: continuous integration, continuous delivery, continuous deployment, intégration continue, livraison continue, déploiement continu, pipeline, github actions, gitlab ci, jenkins, workflow
fr: Chaîne automatique qui, à chaque envoi de code, le construit, lance les tests puis (livraison continue) le déploie. L'intégration continue détecte tôt qu'un changement casse quelque chose ; la livraison continue rend les mises en ligne banales.
en: An automatic chain that, on every code push, builds it, runs the tests and then (continuous delivery) deploys it. Continuous integration detects early that a change breaks something; continuous delivery makes releases routine.
ex: yaml
| on: [push]
| jobs:
|   verifier:
|     runs-on: ubuntu-latest
|     steps:
|       - uses: actions/checkout@v4
|       - run: npm ci
|       - run: npm test
ex-fr: Un workflow GitHub Actions : à chaque push, récupérer le code, installer, tester.
ex-en: A GitHub Actions workflow: on every push, fetch the code, install, test.
voir: test-unitaire, deploiement, build, github, yaml
schema: outils-ci-cd

@ docker
cat: outils
nom: Docker
alias: conteneur, container, dockerfile, image docker, docker compose, kubernetes, containerisation, docker run
fr: Outil qui exécute une application dans un conteneur : un environnement isolé et léger qui embarque tout ce dont elle a besoin (système de base, bibliothèques, code). Elle tourne de la même façon sur n'importe quelle machine.
en: A tool that runs an application in a container: a light, isolated environment that carries everything it needs (base system, libraries, code). It runs the same way on any machine.
+fr: Une image est le modèle figé, décrit par un Dockerfile ; un conteneur est une instance qui tourne. Contrairement à une machine virtuelle, un conteneur partage le noyau du système hôte : il démarre en une seconde.
+en: An image is the frozen template, described by a Dockerfile; a container is a running instance. Unlike a virtual machine, a container shares the host system's kernel: it starts in a second.
ex: yaml
| FROM node:22-alpine
| WORKDIR /app
| COPY . .
| RUN npm ci
| CMD ["node", "serveur.js"]
ex-fr: Un Dockerfile : partir d'une image Node, copier le projet, installer les dépendances, lancer le serveur.
ex-en: A Dockerfile: start from a Node image, copy the project, install the dependencies, launch the server.
voir: vm, sandbox, ci-cd, yaml, deploiement
schema: outils-docker

@ debugger
cat: outils
nom: Débogueur
nom-en: debugger
alias: debugger, debug, breakpoint, point d'arrêt, pas à pas, step over, watch, inspect, console.log, pdb
fr: Outil qui exécute un programme sous contrôle : on pose des points d'arrêt (breakpoints), le code s'arrête à ces endroits, et on avance instruction par instruction en observant la valeur des variables.
en: A tool that runs a program under control: you set breakpoints, the code stops at those places, and you advance instruction by instruction while watching the variables' values.
ex: js
| function moyenne(notes) {
|   debugger;
|   return notes.reduce((a, b) => a + b) / notes.length;
| }
ex-fr: L'instruction debugger arrête l'exécution à cet endroit quand les outils de développement sont ouverts.
ex-en: The debugger statement stops execution at that spot when the developer tools are open.
voir: debogage, devtools, console-log, ide, exception

@ semver
cat: outils
nom: SemVer
dev: Semantic Versioning
nom-fr: gestion sémantique de version
alias: semantic versioning, versionnage sémantique, numéro de version, major minor patch, 1.2.3, ^1.2.3, ~1.2.3, breaking change
fr: Convention de numérotation MAJEUR.MINEUR.CORRECTIF (2.4.1) qui dit quoi attendre d'une mise à jour : un correctif corrige sans rien changer, une version mineure ajoute sans casser, une version majeure peut casser la compatibilité.
en: A numbering convention MAJOR.MINOR.PATCH (2.4.1) that says what to expect from an update: a patch fixes without changing anything, a minor version adds without breaking, a major version may break compatibility.
+fr: Dans package.json, ^1.2.3 accepte toute version 1.x plus récente ; ~1.2.3 seulement les correctifs 1.2.x. Passer à la version majeure suivante est toujours un choix conscient.
+en: In package.json, ^1.2.3 accepts any newer 1.x version; ~1.2.3 only the 1.2.x patches. Moving to the next major version is always a conscious choice.
voir: release, tag, package-json, changelog
schema: outils-semver
