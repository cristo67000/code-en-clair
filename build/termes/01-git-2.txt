# Git et GitHub — seconde moitié : partager, défaire, comprendre les entrailles.

@ remote
cat: git
nom: Remote
nom-fr: dépôt distant
alias: git remote, dépôt distant, remote repository, serveur distant
fr: Dépôt Git hébergé ailleurs (GitHub, un serveur d'entreprise…) auquel votre dépôt local est relié par un nom court et une adresse. On y envoie et on y récupère des commits.
en: A Git repository hosted elsewhere (GitHub, a company server…) to which your local repository is linked by a short name and an address. You send commits to it and fetch commits from it.
+fr: Un dépôt local peut connaître plusieurs remotes. Le nom d'usage du premier est origin ; celui du projet d'origine, quand on travaille sur un fork, est upstream.
+en: A local repository can know several remotes. The usual name of the first is origin; the name of the original project, when you work on a fork, is upstream.
ex: bash
| git remote -v
| git remote add upstream https://github.com/auteur/projet.git
ex-fr: Lister les remotes avec leurs adresses, puis en ajouter un nommé upstream.
ex-en: List the remotes with their addresses, then add one named upstream.
voir: origin, upstream, fetch, push, clone
schema: git-remote

@ origin
cat: git
nom: origin
alias: origin/main, git origin, remote origin
fr: Nom donné par défaut au dépôt distant dont on a cloné le projet. C'est une simple étiquette : origin/main désigne la copie locale de la branche main telle qu'elle était sur ce serveur à votre dernier fetch.
en: The default name given to the remote repository you cloned a project from. It is just a label: origin/main designates the local copy of the main branch as it was on that server at your last fetch.
ex: bash
| git remote get-url origin
| git log origin/main..main
ex-fr: Lire l'adresse d'origin, puis lister les commits de main qui ne sont pas encore sur origin/main.
ex-en: Read origin's address, then list the commits on main that are not on origin/main yet.
attention-fr: origin n'a rien de spécial pour Git : on peut le renommer ou le supprimer.
attention-en: origin is nothing special to Git: you can rename or delete it.
voir: remote, upstream, clone, push
schema: git-remote

@ upstream
cat: git
nom: upstream
alias: upstream branch, branche amont, amont, set-upstream, -u
fr: Deux emplois proches : le remote qui désigne le projet d'origine quand on travaille sur un fork, et la branche distante qu'une branche locale suit, ce qui permet de taper git push ou git pull sans arguments.
en: Two close uses: the remote naming the original project when you work on a fork, and the remote branch that a local branch tracks, which lets you type git push or git pull with no arguments.
ex: bash
| git push --set-upstream origin ma-fonction
| git branch -vv
ex-fr: Envoyer une nouvelle branche en la reliant à sa branche distante, puis voir à quoi chaque branche est reliée.
ex-en: Push a new branch and link it to its remote branch, then see what each branch is tracking.
voir: remote, origin, fork, push, pull
schema: git-remote

@ fetch
cat: git
nom: Fetch
alias: git fetch, fetch(), fetch api, requête javascript, récupérer
sens: Git | Git
fr: Commande qui télécharge depuis le dépôt distant les nouveaux commits et met à jour les branches distantes (origin/main), sans toucher à vos branches ni à vos fichiers.
en: A command that downloads new commits from the remote repository and updates the remote-tracking branches (origin/main), without touching your branches or your files.
+fr: C'est la façon prudente de voir ce qui a changé avant de décider de fusionner. git pull est un fetch suivi d'une fusion.
+en: It is the cautious way to see what changed before deciding to merge. git pull is a fetch followed by a merge.
ex: bash
| git fetch origin
| git log main..origin/main --oneline
ex-fr: Récupérer les nouveautés, puis lister les commits présents sur origin/main mais pas sur main.
ex-en: Fetch the updates, then list the commits on origin/main that are not on main.
schema: git-fetch
sens: JavaScript (web) | JavaScript (web)
fr: Fonction JavaScript intégrée au navigateur qui envoie une requête HTTP et renvoie une promesse qui se résout avec la réponse. C'est la manière moderne d'appeler une API depuis une page web.
en: A JavaScript function built into the browser that sends an HTTP request and returns a promise that resolves with the response. It is the modern way to call an API from a web page.
+fr: fetch ne rejette la promesse que si le réseau échoue : une réponse 404 ou 500 « réussit », il faut tester response.ok soi-même.
+en: fetch only rejects the promise when the network fails: a 404 or 500 response “succeeds”, so you must test response.ok yourself.
ex: js
| const reponse = await fetch('/api/termes.json');
| if (!reponse.ok) throw new Error('HTTP ' + reponse.status);
| const termes = await reponse.json();
ex-fr: Télécharger un fichier JSON, vérifier le code de statut, puis en lire le contenu.
ex-en: Download a JSON file, check the status code, then read its content.
voir: pull, remote, promesse, http, api

@ pull
cat: git
nom: Pull
alias: git pull, tirer, git pull --rebase

en: A command that updates the current branch from the remote repository: it runs a fetch, then merges (or rebases) the new commits into your branch and your working tree.
ex: bash
| git pull
| git pull --rebase
ex-fr: Récupérer et fusionner, ou récupérer et rejouer ses propres commits par-dessus (rebase).
ex-en: Fetch and merge, or fetch and replay your own commits on top (rebase).
attention-fr: Ne pas confondre avec une pull request : le pull est une commande locale, la pull request une demande de fusion sur GitHub.
attention-en: Not to be confused with a pull request: a pull is a local command, a pull request is a merge proposal on GitHub.
voir: fetch, merge, rebase, push, pull-request
schema: git-pull

@ reset
cat: git
nom: Reset
alias: git reset, --soft, --mixed, --hard, annuler
fr: Commande qui déplace la branche courante vers un autre commit, et, selon le mode, remet aussi l'index (--mixed, par défaut) et le dossier de travail (--hard) dans cet état.
en: A command that moves the current branch to another commit and, depending on the mode, also resets the index (--mixed, the default) and the working tree (--hard) to that state.
+fr: --soft défait seulement le commit et garde tout en attente ; --mixed garde les fichiers mais vide l'index ; --hard efface aussi les modifications de vos fichiers, sans retour.
+en: --soft only undoes the commit and keeps everything staged; --mixed keeps the files but empties the index; --hard also erases your file changes, with no way back.

| git reset --hard origin/main
ex-fr: Défaire le dernier commit en gardant ses modifications, ou aligner la branche sur le distant en jetant tout le reste.
ex-en: Undo the last commit while keeping its changes, or align the branch with the remote and throw everything else away.
attention-fr: Reset réécrit l'historique local ; pour annuler un commit déjà partagé, utilisez plutôt revert.
attention-en: Reset rewrites local history; to undo a commit that has already been shared, use revert instead.
voir: revert, checkout, head, reflog
schema: git-reset

en: A Git repository included inside another one, at a specific location and pinned to a given commit. The main repository does not hold its code, only the address and the commit to fetch.

| git submodule add https://github.com/auteur/lib.git vendor/lib
| git submodule update --init --recursive

ex-en: Add a submodule, then initialize those of a freshly cloned repository.

alias: git tag, étiquette, version, release tag, v1.0
fr: Étiquette fixe posée sur un commit précis, en général pour marquer une version publiée (v1.0.0). Contrairement à une branche, elle ne bouge pas quand on ajoute des commits.
en: A fixed label placed on a specific commit, usually to mark a released version (v1.0.0). Unlike a branch, it does not move when commits are added.
+fr: Un tag léger est un simple nom ; un tag annoté est un objet complet avec auteur, date et message. Les tags ne partent pas avec un push ordinaire : git push --tags.
+en: A lightweight tag is just a name; an annotated tag is a full object with an author, a date and a message. Tags are not sent by an ordinary push: use git push --tags.
ex: bash
| git tag -a v1.0.0 -m "Première version"
| git push origin v1.0.0
ex-fr: Créer un tag annoté sur le commit courant, puis l'envoyer au dépôt distant.
ex-en: Create an annotated tag on the current commit, then send it to the remote repository.
voir: commit, branch, release, semver
schema: git-tag
